# Android 音声播放器：需求分析与功能规划

版本：v0.2 · 日期：2026-10-23 · 状态：需求基线；已开始原生 Android 实现，开发与验证状态见项目 README

## 1. 产品目标与已确认需求

开发一款面向本地 DLsite 日语音声收藏的 Android 播放器。用户选择存放音声的目录后，应用识别作品、整理轨道、关联封面和已有字幕，形成可以直接播放的作品库；切换应用或熄屏后继续播放，并能在使用其他应用时显示悬浮歌词。

功能要求：

- 大多数作品目录带 RJ 编号，因此首版以 RJ 编号作为作品识别的重要依据。
- 已有本地字幕文件，因此首版重点是字幕匹配、同步与悬浮显示；实际目录发现 LRC、SRT、VTT、ASS 四类字幕。
- 兼容至少 2020 年之后的 Android 系统与更多品牌手机。
- 作品库和以作品为单位的播放列表需要展示封面，首版提供从图片文件手动选择作品封面的入口。
- 声优 / 社团筛选、自定义播放列表属于首版必需功能。
- 同一作品通常仅保存 MP3 或 WAV 中的一种，常规界面直接显示轨道；确有多个版本时再展示版本切换。
- 本次先完成需求分析与功能规划。

暂定产品选择：

- 本地优先，核心流程离线可用，作品信息主要从目录、文件名和现有标签提取。
- “整理”指建立应用内索引和作品播放列表，默认不移动、重命名或修改源文件。
- 最低支持 Android 10 / API 29，覆盖 2020 年在用的 Android 10 设备及后续版本；对多个 Android 版本及不同厂商系统执行兼容测试。
- 首版覆盖手机上的音频收藏与播放。视频播放、压缩包内直接播放、联网作品信息补全、自动转写作为后续候选。

## 2. 核心使用流程

首次使用：添加音声目录 → 系统授予目录访问 → 递归扫描 → 自动识别作品与音频版本 → 展示扫描结果与待确认项 → 进入作品库 → 选择版本播放 → 自动加载字幕 → 按需启用桌面歌词。

后续使用：打开作品库 → 继续上次作品与进度，或搜索 RJ / 标题 → 播放。新增文件后执行增量刷新，保留已有的手动整理和播放进度。

导入不强制逐项确认：高可信结果直接建立作品，低可信或冲突项目列入“待整理”，用户可立即试听并随时修正。

## 3. 数据结构：作品、版本、轨道、播放列表

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 文件来源 | 用户授权的目录树 | 内部存储的 Audio/DLsite、SD 卡上的音声目录 |
| 作品 | 收藏和继续收听的主要单位 | RJ01234567 对应的一部作品 |
| 音频版本 | 同一作品下供用户选择的音频集合 | MP3 版、WAV 版、无 BGM 版、不同语言版 |
| 轨道 | 一个实际音频文件 | 01_プロローグ.mp3 |
| 作品播放列表 | 指定版本下按顺序播放的轨道集合 | 本篇 01—10，特典单独展示 |
| 当前队列 | 当前一次播放使用的有序快照 | 用户从作品详情点击播放后生成 |
| 自定义播放列表 | 用户按顺序组织的作品或单条轨道集合，首版支持 | 整部作品加入“睡前收藏”，以作品封面卡片展示，可展开轨道 |

作品、轨道采用应用内部稳定 ID；RJ 是可缺省的外部编号，不直接充当所有数据库记录的主键。不同存储位置保留来源信息，不能因为标题相同就覆盖另一份收藏。

作品字段至少包括：RJ、原始目录名、展示标题、封面、来源目录、版本集合、识别依据、待确认状态、收藏状态和最后收听位置。声优与作品、社团与作品使用关联记录，以支持一部作品有多位声优或多个合作社团。社团 / 声优只有在本地信息明确或用户补充时填写；不能仅凭一对方括号就认定字段含义。

自定义列表条目保留“作品 / 单轨”类型和对应内部 ID。整部作品条目在开始播放时按当前选择的版本、分组和轨道顺序展开为队列快照；扫描更新不会中途替换该队列。列表中删除作品条目只修改列表，不删除源文件。

## 4. 自动整理规则

### 4.1 扫描与作品边界

1. 扫描已授权目录下的子目录，收集音频、图片与字幕；保留原始名称、相对目录关系和内容 URI。
2. 用户既可以选择包含多部作品的总目录，也可以选择单个作品目录。
3. 优先使用用户已经确认的归属规则，其次识别目录中的明确 RJ 编号，最后考虑文件名编号、目录结构和音频标签。
4. RJ 匹配处理大小写与常见全角字符，保留原编号的数字及前导零。只在识别用文本上规范化，展示与源文件名保持原样。
5. 最近的、明确命名的作品目录通常作为作品边界；WAV、MP3、Disc1、字幕、特典等子目录不直接拆成独立作品。
6. 父目录、子目录或文件名出现互相矛盾的 RJ 时标记冲突，保留来源供用户确认。
7. 没有 RJ 时，根据明确的候选作品目录建立临时作品；禁止把所有无编号音频合并成一个“未知作品”。扁平目录且无可靠分组线索时，暂放待整理，提供按目录或所选文件归组的操作。
8. 嵌套授权目录避免重复导入同一内容；不同来源中的同 RJ 可归到同一作品，但保留独立副本 / 版本。无法确认文件身份时不直接去重或覆盖。
9. 对“总目录 → 社团目录 → RJ 作品 → 内层同 RJ 包装目录 → 音频”递归识别：社团容器不当作作品，同 RJ 的重复包装层不另建作品。
10. 一个目录有多个不同 RJ 时，先视为待确认集合；子目录若明确标明归属则分别归组，否则不擅自将多个编号设为同一作品的别名。
11. 对 PC 程序资源、游戏音效及解包素材建立可查看的资源候选分组，默认不加入普通作品队列；结合程序结构判断，不能单凭 `.ogg` 或 `voices` 名称一律排除。独立可播的音声目录仍可导入，用户可手动包含资源目录。

### 4.2 音频版本、内容分组与排序

- 常规作品仅有 MP3 或 WAV 时直接展示本篇轨道，不增加必须先选格式的操作；确有两种格式时显示版本切换，默认只将一个选中版本加入队列。
- “有 BGM / 无 BGM”“日语 / 其他语言”等可能对应不同音频内容，应作为版本区分，不能仅按相同序号折叠文件。
- Disc1 / Disc2 是同一版本的分卷，按卷号再按轨道号排列。
- 本篇、特典、试听作为内容分组。识别不明确时显示原目录名称，不静默丢弃文件；是否将特典加入队列可选。
- 排序优先使用明确的卷号和文件名前缀轨道号，其次使用一致可靠的轨道标签，最后进行自然排序，使 2 排在 10 前面。
- 手动调整归属、版本和顺序后，后续扫描保留用户设置；提供恢复自动整理的入口。
- 单纯文件名相同、文件大小相同或时长相近均不足以认定为完全重复。首版先展示候选重复项；完整内容校验按需进行。

示例输入（虚构编号与标题）：

```text
DLsite/
  [RJ01234567] 眠りの時間/
    cover.jpg
    MP3/
      01_プロローグ.mp3
      02_耳かき.mp3
      10_おやすみ.mp3
    WAV/
      01_プロローグ.wav
      02_耳かき.wav
      10_おやすみ.wav
    字幕/
      MP3/
        01_プロローグ.ja.lrc
        02_耳かき.zh.srt
    特典/
      おまけ.mp3
```

期望结果：一个作品 RJ01234567；MP3、WAV 两种可选版本；本篇顺序为 01 → 02 → 10；特典单列。字幕目录通过作品范围、版本目录和同名轨道建立候选关联；不同版本之间不默认共享可能存在时间差的字幕。

### 4.3 封面与名称

- 作品库、作品详情和自定义播放列表中的整部作品条目共享同一张作品封面。
- 首版提供“更换封面”：从当前作品图片候选或系统文件选择器选择图片，预览后保存，并提供恢复自动封面入口。
- 用户选择的图片保存为应用私有持久文件中的封面副本，生成缩略图用于列表显示，避免原图片移动或临时授权失效导致手动封面丢失；不修改原图片和音频标签。
- 优先使用用户指定封面，其次选择作品目录中明确命名的 cover / folder / jacket 图片，再查找用户已授权封面目录中同 RJ 的图片，最后考虑音频内嵌封面。
- 支持设置独立封面目录。实际样本存在 `封面集/RJ编号.jpg` 和 `.png`；同 RJ 有多张图时展示候选供用户选择，不只取任意首张。
- 其他图片作为候选供选择，避免将说明图自动认定为封面；无图片时显示占位图。
- 标题可去除已经单独展示的 RJ 和明确的编码 / 格式信息；原始名称始终可查看。
- 不默认删除括号中的正文，也不将模糊推断的社团或声优显示成已确认信息。

### 4.4 增量扫描与文件变化

- 通过 URI、相对位置、大小和修改时间等建立文件索引；不同文档提供方可能缺少部分元数据，不能仅依赖时间戳。
- 重复扫描不重复创建作品和轨道；只补充新增项并刷新有变化的信息。
- 扫描可取消，展示已发现文件数、已整理作品数与失败数。无法预先知道总量时不显示虚假的完成百分比。
- 只有目录扫描完整成功后，才将此前存在但此次未发现的项目标记为缺失；取消、权限失效或 SD 卡未挂载均不能触发批量移除。
- 文件缺失保留历史和用户整理结果，提供重新定位入口。跨目录移动、重命名或重新授权后无法可靠关联时，让用户选择重新关联。
- 扫描结果更新不重置正在播放的队列或进度。
- 首版支持手动刷新、添加目录后扫描与进入应用时按需检查。SAF 提供方能力不同，不承诺对所有目录实时监听文件变化。

## 5. 本地字幕与桌面歌词

### 5.1 字幕匹配与解析

首版支持 LRC、SRT、WebVTT 与 ASS 的时间轴和文本显示，统一转换为包含开始时间、结束时间（若存在）、文本和语言的字幕条目，供应用内与悬浮窗口共用。ASS 首版提取对话和时间，处理换行及样式标记，不要求还原视频中的复杂排版和特效。实际调研有 684 个 VTT 文件，不能只支持 LRC / SRT。

匹配优先级：用户手动绑定 → 同目录同基本文件名 → 当前作品 / 版本字幕目录中的同基本文件名与语言后缀 → 可供用户选择的候选。

匹配同时支持 `轨道名.wav.vtt`、`轨道名.mp3.vtt` 这样的双扩展名：先移除字幕扩展名，再识别可选音频扩展名；只在识别用文本中处理 Unicode 组合字符和多余空白，不改写原始名称。纯数字轨道号只能作为当前作品 / 版本范围内的候选证据，不能单独自动绑定。

- 识别 ja / jp / zh / cn 等常见语言标记作为提示，不把后缀存在当作内容语言已验证。
- 不凭“01”“track1”在整个作品库里跨作品搜索匹配；存在多个候选时需要用户选择。
- 默认以单轨起点作为字幕时间零点。整部作品共用一份全局时间轴的字幕，首版提供手动说明或延后适配，不能直接套到每条轨道。
- LRC 支持行级时间戳、多时间戳与 offset；SRT 尊重开始 / 结束时间，在空白区间停止显示上一句。
- VTT 处理 WEBVTT 文件头、提示时间区间和文本；同一音频有多种字幕格式时均保留为可选字幕，默认选中一份，不重复叠加显示。
- 尝试处理 UTF-8 / BOM、UTF-16、Shift_JIS 等常见编码，提供手动编码选择解决乱码。
- 支持切换已有语言字幕、逐轨保存时间偏移。独立双语字幕仅在能够明确关联时组合；否则由用户切换。
- 拖动、暂停、切轨和变速后，重新依据播放器媒体时间同步，不能靠独立累计计时。
- 无匹配字幕时显示“未找到字幕”与手动选择入口。自动转写、自动翻译不属于首版必需功能。

### 5.2 桌面歌词行为

- 在其他应用上方显示当前字幕，可拖动、调字体 / 颜色 / 透明度，并支持锁定位置和触摸穿透。
- 提供恢复交互和关闭入口，避免触摸穿透后无法关闭。首次使用时再引导开启“显示在其他应用上层”的系统授权。
- 用户拒绝或撤销授权，只影响悬浮显示，应用内字幕和音频播放继续工作。
- 显示当前句，可选显示下一句；默认不自动滚动展示完整剧本。
- 熄屏时停止界面刷新，音频继续；亮屏后按当前播放时间立即恢复同步。
- 默认锁屏时隐藏悬浮字幕。锁屏提供标准媒体控制；不将跨锁屏悬浮歌词作为首版承诺。

Android 的跨应用悬浮窗口需要专门授权，使用 `SYSTEM_ALERT_WINDOW` 与 `TYPE_APPLICATION_OVERLAY` 等系统能力。该权限与后台播放相互独立。[官方授权说明](https://developer.android.com/reference/android/provider/Settings#canDrawOverlays(android.content.Context))、[窗口类型说明](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY)。

## 6. 播放与后台行为

首版播放功能：

- 播放 / 暂停、上一轨 / 下一轨、进度拖动、快退 / 快进、作品内顺序播放与单轨循环。
- 默认作品结束后停止，避免自动跳到其他作品；可选作品循环。
- 按作品和所选版本记忆最后轨道、播放进度与字幕选择，提供“继续收听”。
- 变速播放尽量保持音调；默认保留立体声和声道方向，不默认开启混音、单声道或改变音色的处理。
- 睡眠定时支持固定时长和当前轨道结束后停止。
- 优先验证 MP3、M4A/AAC、FLAC、PCM WAV、Ogg/Vorbis、Opus 常见文件；实际兼容性按容器、编码、采样参数和目标设备验证，不根据扩展名承诺全部可播。[Media3 格式说明](https://developer.android.com/media/media3/exoplayer/supported-formats)。

后台设计：播放器与媒体会话运行在 `MediaSessionService` 中，界面通过 `MediaController` 控制同一个播放器；使用媒体播放类型的前台服务与标准媒体通知。[Android 官方方案](https://developer.android.com/media/media3/session/background-playback)。

| 场景 | 目标行为 |
| --- | --- |
| 按 Home 或切换其他应用 | 持续播放，可从通知控制 |
| 锁屏 / 熄屏 | 持续播放，可从系统锁屏控制 |
| 从最近任务移除界面 | 播放进行中时按继续播放设计，并进行实际机型验证 |
| 耳机拔出 / 蓝牙断开 | 默认暂停，避免切换到外放继续播放 |
| 来电 / 其他应用取得音频焦点 | 暂停或按系统策略处理，不与对方持续抢占焦点 |
| 短暂中断结束 | 仅在确由该中断导致暂停且系统允许时按设置恢复 |
| 用户点击停止 | 停止播放，释放相应资源 |
| 系统终止进程 / 用户强制停止 / 重启 | 持久化的队列与进度可供下次恢复；不自动强行重播 |

定期保存进度，并在暂停、切轨等关键动作保存。建议将异常退出的进度损失控制在约 5 秒以内，作为验证目标。

后台播放需要遵循音频焦点管理；语音类内容适合设置对应的音频属性。[官方音频焦点说明](https://developer.android.com/media/optimize/audio-focus)。

厂商省电策略是兼容性验证项目：如实际设备限制播放，提供对应设置指引。不能把“后台播放”表述为任何强制停止和系统终止下都永不中断。

## 7. 页面规划

| 页面 | 主要内容与操作 |
| --- | --- |
| 作品库 | 封面、标题、RJ、轨道数、声优 / 社团、收听进度；搜索、排序与多条件筛选；添加来源；继续收听 |
| 扫描结果 / 待整理 | 新增作品、冲突、未归组文件、缺失项；查看识别依据并纠正 |
| 作品详情 | 单版本直接展示轨道，多版本可切换；本篇 / 特典 / 分卷；从头播放 / 继续；更换封面、编辑声优 / 社团、加入自定义列表 |
| 自定义播放列表 | 新建 / 重命名 / 删除列表；添加整部作品或单轨；作品条目展示封面；调整顺序、移除条目和连续播放 |
| 播放页 | 封面、作品与轨道名、进度、快进退、队列、字幕、变速、循环和睡眠定时 |
| 来源与设置 | 已授权目录、重新扫描 / 授权、字幕编码与样式、悬浮歌词、后台设置与诊断 |

作品库、列表与详情页保留迷你播放器，点击返回完整播放页。首版底部导航建议为“作品库 / 播放列表 / 设置”，不把全部音频平铺为唯一入口。

声优 / 社团筛选支持多选；同一筛选维度内按“任一匹配”，不同维度之间按“同时满足”，并提供“信息未填写”入口和清除筛选按钮。识别 `CV` / `声優` 等明确标记时提取候选声优；带括号的普通目录名只作为社团候选，允许用户确认某一级目录代表社团并应用到子作品。多人名字或别名不明确时保留原文供编辑，不强行按空格拆分。

自定义列表的整部作品条目默认展示封面、标题、RJ 和收听进度，展开后查看曲目。列表缺失源文件时保留条目并标记不可用，重新关联后恢复，不静默移除。跨作品连续播放用于用户显式选择的列表；直接播放单部作品时仍默认在作品结束后停止。

## 8. 功能优先级与阶段交付

| 阶段 | 功能范围 | 完成标志 |
| --- | --- | --- |
| P0-A：导入与整理 | 目录授权、RJ 优先分类、无编号回退、社团容器 / 重复包装层 / 多 RJ、资源候选、版本 / 分卷、自然排序、手动纠正、增量刷新 | 代表性目录能正确生成作品播放列表，重复扫描不增生、不覆盖人工修正 |
| P0-B：作品库与自定义列表 | 作品封面展示与手动选择、独立封面目录、搜索、声优 / 社团编辑及筛选、自定义列表的作品 / 单轨条目与排序 | 能用封面浏览作品，按声优 / 社团找到作品并组织到自定义列表 |
| P0-C：播放与后台 | 常见音频播放、作品 / 列表队列、进度恢复、通知 / 锁屏 / 耳机控制、音频焦点、变速与睡眠定时 | 切后台和熄屏连续播放，异常场景行为明确 |
| P0-D：字幕与桌面歌词 | LRC / SRT / VTT / ASS 文本时间轴、双扩展名匹配、手动绑定、编码与偏移、应用内字幕、悬浮授权和样式 | 字幕与播放同步，授权拒绝不影响播放 |
| P1：收藏与管理增强 | 自定义标签、时间点书签、批量整理、收藏与整理规则备份 / 恢复、CUE 分轨 | 较大收藏库维护方便，手动整理结果可迁移 |
| P2：可选扩展 | 在线作品信息补全、NAS / WebDAV、其他字幕格式、离线转写与翻译、视频与压缩包支持 | 根据真实使用反馈分别评估 |

P0-A 至 P0-D 共同组成首个完整可用版本；桌面歌词、手动封面、声优 / 社团筛选和自定义播放列表均属于首版核心需求。阶段划分用于逐步验证，不代表只交付分类功能。

暂不作固定工期承诺：目录样本复杂度、目标手机、开发环境和兼容测试范围明确后，再细化任务和时间估算。

## 9. 建议技术方案

| 层次 | 建议 | 目的 |
| --- | --- | --- |
| 应用与界面 | Kotlin + Jetpack Compose | 原生 Android 交互，便于接入平台媒体和窗口能力 |
| 文件访问 | Storage Access Framework、持久化目录 URI 授权 | 用户选择目录，读取音频及相邻图片 / 字幕 |
| 整理规则 | 独立的 Kotlin 规则模块 | 通过目录清单验证分组、排序与冲突规则，不耦合界面 |
| 数据存储 | Room + DataStore | 存储作品 / 版本 / 轨道 / 声优 / 社团 / 列表条目 / 绑定 / 历史与用户设置 |
| 播放 | AndroidX Media3 ExoPlayer + MediaSessionService | 统一播放状态，支持后台与系统媒体控制 |
| 字幕 | LRC / SRT / VTT / ASS 解析与统一时间轴 | 应用内和悬浮显示共享字幕状态 |
| 异步任务 | Kotlin Coroutines；必要时使用可恢复任务机制 | 可取消扫描、分批入库与按需读取元数据 |

文件访问使用内容 URI，不假设所有文件都有可直接访问的真实磁盘路径。先枚举文件和建立作品，再按需读取时长、标签和图片，避免导入前必须解码所有音频。

Android 11 起，目录选择不能直接授权内部存储根目录、Download 根目录以及部分受限目录。引导使用可授权的音声子目录，例如 `Download/DLsite` 或 `Music/Voice`，以实际系统文件选择器结果为准；保留重启后的 URI 授权，并处理权限撤销。[官方目录访问与限制](https://developer.android.com/training/data-storage/shared/documents-files)。

参考项目暂取 [rRemix/APlayer](https://github.com/rRemix/APlayer)：可借鉴其文件夹入口、播放页、悬浮歌词和系统控制交互。该项目页面标注 GPL-3.0；实际进入开发时再比较独立实现与派生改造的成本，并在复用前核对具体代码及许可证。当前规划推荐先围绕作品数据结构设计，再决定复用范围。

## 10. 验收与兼容性计划

以下是待实施时验证的验收目标，不代表当前已有测试结果。

1. 带 RJ 的作品总目录和单作品目录均能导入；不同作品下的同名 `01.mp3` 不混淆。
2. 同 RJ 的 MP3 / WAV 不在默认队列中重复播放；不同内容版本和特典保持可区分。
3. Disc1 / Disc2 和 1、2、10 的轨道顺序正确；日文、中文、空格与括号名称正常显示。
4. 无 RJ、多 RJ 冲突、扁平目录和缺失标签都有明确回退行为，并可手动修正。
5. 第二次扫描不重复创建记录；手动标题、归属、顺序和字幕绑定仍保留；取消扫描和未挂载 SD 卡不造成误删。
6. 在约定的参考手机、正常后台设置下，切换应用 / 熄屏连续播放至少 2 小时并跨轨；记录系统版本、机型与电池设置。
7. 通知、锁屏、蓝牙 / 有线耳机控制可用；耳机断开、来电与焦点变化符合规划。
8. 重开应用可以继续上次轨道；异常结束后的进度误差以约 5 秒以内为目标。
9. LRC / SRT / VTT / ASS 文本在暂停、拖动、切轨和变速后同步，双扩展名正确匹配；已知时间戳样本的显示更新时间误差以 300 毫秒以内为目标，不包含字幕本身制作误差。
10. 拒绝 / 撤销悬浮权限时音频正常；悬浮歌词可移动、锁定、恢复操作和关闭；熄屏不继续高频刷新界面。
11. 无网络时完成导入、分类、播放和字幕显示。源文件在导入前后保持原样。
12. 首轮以约 100 部作品 / 2,000 条轨道测量扫描、搜索和首播表现，再用更大样本检查内存与可取消性；具体耗时阈值根据参考手机与存储介质实测制定。
13. 用户从图片文件指定封面后，作品库、详情和自定义列表中的作品条目一致更新；重启和重新扫描后仍保留，能恢复自动选择。
14. 支持多声优 / 多社团关联，筛选规则明确，无信息作品仍能找到；手动填写与确认结果在重扫后保留。
15. 自定义列表能新建、改名、删除、添加作品 / 单轨、排序、移除和跨作品播放；删除列表或条目不修改源文件。
16. 实际目录中的社团容器、多层同 RJ、多 RJ 集合、独立封面集和程序资源候选均有明确处理；不将全部游戏音效自动加入队列。

验证分为规则测试、设备功能测试与长时播放测试：规则模块使用带预期分类结果的目录清单；媒体兼容性使用实际音频样本；后台与悬浮能力必须进行真机测试。系统覆盖 Android 10 / API 29、Android 11 的目录限制、Android 12、Android 13 及以上媒体控制，以及实施时最新稳定系统。Android 手机 重点验证 厂商系统 后台限制与悬浮授权；其他品牌可先覆盖系统模拟器，再补充可获得的真机，不能将模拟器通过等同于所有厂商品牌已验证。

## 11. 实际目录与开发环境



真机测试时读取手机实际 Android / API / 厂商系统 版本，避免将“最新系统”固定猜成某一版本。手机的存储来源在首次导入时选择，无需在规划阶段预先绑定电脑目录或手机磁盘路径。
