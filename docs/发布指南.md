# GitHub 仓库与 1.0 发布指南

## 创建仓库

仓库名使用 ysplayer；中文“音声书架”可放在描述和 README 标题中。GitHub 仓库名只接受 ASCII 字母、数字和 . - _。可选择 Public。

已有本地 README、.gitignore、LICENSE，因此创建页面不要预生成这三个文件：README 关闭，Add .gitignore 选 No .gitignore，Add license 选 No license。这只是避免创建一套冲突文件，公开源码会通过本地 LICENSE 明确采用 Apache-2.0。

建议描述：面向本地音声收藏的 Android 播放器，支持 RJ 整理、社团/多人声优筛选、后台播放和悬浮字幕。

## 文件边界

源码、测试、数据库 schema、Gradle Wrapper、构建脚本、许可文件和文档提交到仓库。不要排除 Wrapper JAR 或所有 JAR：third_party 中的原版 MPL 源码 JAR 是刻意保留的合规材料。

.gitignore 已排除本地 SDK 配置、IDE 与构建缓存、所有日志、APK/AAB、artifacts、环境密钥文件及 private-signing。它不会删除本地文件，也不能把已提交的秘密从历史中抹去。首次提交前检查暂存区；本项目没有把签名私钥写进源码或公开归档。

## 签名

正式 APK 采用独立发布证书；preview 继续使用测试签名。两者签名不同，旧 preview 通常不能直接被正式版覆盖。当前未提供应用数据导出/迁移，卸载旧版会丢失应用内部设置、收藏、列表和历史，源音声文件保留。需要这些数据时先保留旧安装，不要直接卸载。

发行附件同时提供 1.0.0-preview，沿用既有测试签名，可供旧测试安装覆盖升级并保留数据。它供原有测试用户使用；GitHub 的主下载应标为独立签名的 1.0.0 正式包，不要混用两种签名。

本机发布配置保存在被忽略的 private-signing/release.properties，私钥为该目录下的 ysplayer-release.p12。请将整个私有目录加密备份到独立安全位置；不要上传 GitHub，不要随发布附件分发。以后更新同一应用必须使用同一密钥并增加 versionCode。

其他构建者可依据根目录 release-signing.properties.example 创建自己的配置及密钥；debug 构建无需发布密钥。未配置密钥时正式打包会失败，不会悄悄生成调试签名的正式版本。

    ./gradlew :app:assembleRelease

## MPL 1.1 与许可材料

无需为使用 juniversalchardet 额外付费或把整个应用改成 MPL。本发行选择按 MPL 1.1 提供该库，保留完整原作者声明，已把准确版本原始源码、原始 Maven POM 和构建说明随 APK 提供，并提供离线导出入口。

发布时保留 app/src/main/assets/legal、third_party、LICENSE、NOTICE、THIRD_PARTY_NOTICES.md。发布者后续修改该库时，必须提供对应修改后的源码并保留 MPL 许可；不能仍声称使用未修改的旧源码包。保留公开发行版本及其对应源码归档。

## Release 附件

为对应源码提交创建 v1.0.0 标签与 Release，上传正式 APK、SHA-256 校验文件，以及可选的源码 ZIP 和单独 MPL 库源码 ZIP。APK 不必提交进 Git 历史。源码 ZIP 已包含许可资产；第三方源码也随 APK 提供。

若手工通过网页上传源码，应先解压源码 ZIP，然后上传解压后的文件结构；直接上传整个 ZIP 只会让仓库里出现一个压缩包。隐藏文件 .gitignore 也要保留。
